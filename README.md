# Atelier Match — interface prototype

A new React + TypeScript interface implementation for the CSIT314 Renovation Matching Platform. Source files were written in a new project directory. Standard Vite tooling is used directly.

## Run

Use Node.js 22.12+ or Node.js 24.

```sh
npm ci
npm run dev
```

Open the local URL printed in the terminal. To compile and preview production output:

```sh
npm run build
npm run preview
```

## Scope

Four role layouts cover the 48 numbered user stories as visual screens: User Admin, Interior Designer, Customer and Platform Manager. All routes are open for design review. Use the header's **Preview role** selector or links on the login preview to navigate.

Included: project discovery, project details, favourites, profile/account management forms and confirmation dialogs, company information, current/past portfolios, sample analytics, categories and sample report modes. Desktop and mobile layouts, empty-search states, keyboard-accessible dialogs and preview notifications are included.

This version has no authentication, business-rule engine, APIs, database, browser persistence, activity tracking, file upload or report aggregation. Forms accept visual input; submit/confirm actions show a preview notice without changing sample records. Filters affect only the visible sample list. The numbers in analytics and reports are illustrative. This is an interface deliverable, not the functional implementation of the assignment.

## Files

- `src/App.tsx`: new presentation components and local navigation.
- `src/data.ts`: read-only example records and role navigation.
- `src/styles.css`: new responsive design styling.
- `src/fonts.css` and `public/fonts`: locally bundled fonts and notices.
- `public/images`: local reference interior photos, retained to match the visual reference.
- `STORY_COVERAGE.md`: numbered user-story to screen mapping.
- `dist`: compiled preview, generated by the build script.

The application makes no external browser requests: fonts and photos are bundled locally. Dependency installation requires access to the npm registry. Public frontend assets remain inspectable by the viewer, as with any frontend website.

## Static hosting

Serve `dist` as a static website. Configure fallback to `index.html` for `/admin/*`, `/designer/*`, `/manager/*`, `/login`, `/logout` and `/favourites`. Open the project with a local server, not by double-clicking the HTML file.

## Verification

The interface was checked on all 15 routes in a browser, plus four representative mobile screens. Checks covered dialog opening/dismissal, form-preview notifications without record changes, list empty states, report previews, zero persisted application data and no external browser requests.

## Next phase

Backend implementation, OOP business classes, authorization, persistence, real CRUD/search, analytics, report definitions, large test data and live functional demonstrations remain group work for a later phase. They are deliberately absent from this UI package.
